# CLAUDE.md — CRISalid Apollo

## What this project is

A read-only **GraphQL API** over the CRISalid Institutional Knowledge Graph. It uses [Apollo Server](https://www.apollographql.com/docs/apollo-server/) with the [`@neo4j/graphql`](https://neo4j.com/docs/graphql/current/) library, which auto-generates resolvers from GraphQL type definitions — no resolver code is written manually.

The API is a **mirror** of the graph model maintained by `crisalid-ikg` (the Python middleware). When IKG changes its Neo4j schema, `src/schema.ts` and `tests/data/graph.cypher` must be kept in sync.

```

  data/

  integration/

    organization.test.ts  — organization unit queries, MEMBER_OF / PART_OF
```

## Architecture

`@neo4j/graphql` maps GraphQL type definitions to Neo4j nodes and relationships. Every type annotated with `@node` becomes a queryable entity; `@relationship` fields declare edges; `@relationshipProperties` types carry edge properties. Apollo Server wraps the generated schema with auth middleware.

**No query/mutation resolvers exist in this project** — they are all auto-generated by `@neo4j/graphql` from `schema.ts`.

## Key schema conventions

### OrganizationUnit type labels

`OrganizationUnit` is the base Neo4j label. Each node also carries specific labels that form the taxonomy. The `types` field retrieves them via a `@cypher` statement:

```graphql
types: [String!]! @cypher(statement: "RETURN labels(this) AS types", columnName: "types")
```

Expected label sets by taxonomy level:

| Taxonomy level | Neo4j labels |
|---|---|
| Institution | `OrganizationUnit`, `Institution` |
| InstitutionSubdivision | `OrganizationUnit`, `InstitutionSubdivision` |
| ResearchUnit | `OrganizationUnit`, `Unit`, `ResearchUnit` |
| SupportUnit | `OrganizationUnit`, `Unit`, `SupportUnit` |
| UnitSubdivision | `OrganizationUnit`, `UnitSubdivision` |
| Team | `OrganizationUnit`, `Team` |

### Relationship property types

Two `@relationshipProperties` types carry edge metadata on org-to-org relationships:

- **`OrgMembership`** — on `MEMBER_OF` between OrganizationUnit nodes: `position: String`, `start_date: DateTime`, `end_date: DateTime`
- **`OrgInclusion`** — on `PART_OF` between OrganizationUnit nodes: `start_date: DateTime`, `end_date: DateTime`

Person relationships use separate types:

- **`Membership`** — on `Person -[:MEMBER_OF]-> OrganizationUnit`: `start_date`, `end_date`, `position_code`
- **`Employment`** — on `Person -[:EMPLOYED_AT]-> OrganizationUnit`: `start_date`, `end_date`, `position_code`

### Relationship direction

All `@relationship` directives on `OrganizationUnit` use `direction: OUT` — the traversal follows the actual graph edge direction. In queries, `member_ofConnection` navigates from a node to the org it belongs to, and `part_ofConnection` navigates from a node to the org it is structurally included in.

### Literals and TextLiterals

- **`Literal`** — `language: String!`, `value: String!` — used for `long_labels`, `short_labels`, `local_types`
- **`TextLiteral`** — same fields plus `key: String!` — used for `descriptions` and document abstracts

## Graph model (organization hierarchy)

The test fixture in `tests/data/graph.cypher` contains the authoritative example hierarchy:

```
Université Paris Sud-Ouest (EPE, uai-07890)
  └─ [MEMBER_OF] Université Étienne Dupond (UNIV, uai-02345)
       ├─ [PART_OF] Département de physique (InstitutionSubdivision, local-DEPT-PHY-001)
       └─ [PART_OF] Faculté des sciences (FAC, local-FAC-SCI-001)
            └─ [PART_OF] LRA (UMR, local-123456)
                 ├─ [MEMBER_OF {main_supervision}] Université Étienne Dupond
                 ├─ [MEMBER_OF {associated_supervision}] CNRS (EPST, uai-CNRS)
                 ├─ [MEMBER_OF {associated_supervision}] ENA (GE, uai-ENA-ASTRO)
                 ├─ [MEMBER_OF] Département de physique
                 └─ [PART_OF] Faculté des sciences

Axis (UnitSubdivision, local-AXIS-OBS-001)
  └─ [PART_OF] LRA
Team (TEAM, local-TEAM-ASTRO-001)
  ├─ [PART_OF] LRA
  └─ [MEMBER_OF] Axis
```

Note: UIDs in Apollo's test fixture (e.g. `uai-CNRS`) may differ from IKG-computed UIDs (e.g. `uai-0757581P`). The IKG computes UIDs from identifier values; Apollo's fixture sets them directly.

## Authentication

The server uses API key authentication via the `x-api-key` request header.

- Controlled by `ENABLE_API_KEYS` env var — set to `"false"` to disable (as in `.env.test`)
- Valid keys are comma-separated in `API_KEYS` env var
- Auth is enforced in the Express `context` function, not as a GraphQL directive

## Testing

Tests use Jest with `--runInBand` (sequential execution — they share one Neo4j instance).

### Start the test Neo4j instance

```bash
docker run --publish=7475:7474 --publish=7688:7687 --env=NEO4J_AUTH=none \
  -e NEO4J_apoc_export_file_enabled=true \
  -e NEO4J_apoc_import_file_enabled=true \
  -e NEO4J_apoc_import_file_use__neo4j__config=true \
  -e NEO4JLABS_PLUGINS='["apoc"]' \
  neo4j:5-community
```

Port 7688 is the bolt port used by tests. Port 7475 exposes the Neo4j browser for manual inspection.

### Run tests

```bash
npm run test
```

Tests load `.env.test` (`NEO4J_URI=neo4j://localhost:7688`, `ENABLE_API_KEYS="false"`).

### Test helpers (`tests/setup.ts`)

- `createTestServer()` — builds a fresh `ApolloServer` from the current `typeDefs`; call at the top of each test
- `runCypherFile(path)` — loads a `.cypher` file and runs it as a single transaction; used to populate the graph with `tests/data/graph.cypher`
- Database is wiped (`MATCH (n) DETACH DELETE n`) before all tests and after each test

### Writing integration tests

```typescript
test("...", async () => {
  const server = await createTestServer();
  await runCypherFile("tests/data/graph.cypher");

  const res = await server.executeOperation({ query: QUERY });
  const body = res.body;
  if (body?.kind !== "single") fail("Expected single result");

  const result = body.singleResult;
  if (result.errors) console.error(JSON.stringify(result.errors, null, 2));
  expect(result.errors).toBeUndefined();

  const data = result.data as MyResponseType;
  // ...assertions
}, 20000);  // 20 s timeout — schema build + Neo4j round-trips are slow
```

Always set a `20000` ms timeout. The `@neo4j/graphql` schema build alone takes several seconds.

## Keeping schema and IKG in sync

When `crisalid-ikg` changes the Neo4j graph model (new node labels, new relationship types, new properties), two files must be updated here:

1. **`src/schema.ts`** — add/rename types, fields, `@relationshipProperties`
2. **`tests/data/graph.cypher`** — update the test fixture to match the new model

The integration tests serve as the contract: if they pass against a fresh Neo4j instance seeded from `graph.cypher`, the API correctly exposes the current IKG graph model.
